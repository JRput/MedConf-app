# Mission (APPROVED 2026-10-24): Registration gate for the directory + public homepage front door

**Opened:** 2026-10-24 · **Owner brief:** "users not registered should not be able to access the directory or societies pages and search fully, this needs to be blocked and prompt users to either sign in or create an account. the homepage also lists abstract deadlines and upcoming conferences, allow browsing by specialties etc. for users who have not registered yet. create a plan … report back first and use the relevant design and web skills in the hq repository" · **Protocol:** HQ foreman; plan on Opus; proof-check before close. **Status: BUILDING Phase 1 on localhost:3000 for owner review. NO push to GitHub/Vercel until final approval (owner instruction 2026-10-24).**

## What is true today (explorer map, 2026-10-24, paths under `medconf-website/`)
- The directory is public at THREE layers: (1) routes — `PROTECTED_PATHS` (`src/middleware.ts:25`) excludes `/conferences`, `/conferences/[id]`, `/societies`; the matcher skips `/api`, so `/api/directory` is open and cached `public, s-maxage=300`; (2) data — RLS policies "Anyone can view conferences / pricing tiers / course sessions / scraper sources" have no `TO` clause (anon + authenticated), `directory_events` view and `directory_facets()` RPC are granted to anon (`supabase/migrations/20261002000000_directory_query_layer.sql:129, :323`), published community facts/tiers likewise; (3) copy — homepage metadata and hero say "Free, no account needed" (`src/app/page.tsx:37`, `src/components/home/HomeHero.tsx:21`), HowItWorks points at `/conferences`.
- Homepage (`src/app/page.tsx`, server component, `revalidate = 3600`, anon client, never reads the session) renders: HomeHero (GET form → `/conferences?q=`; 6 quick chips) · Closing soon (≤5 rows) · This month (≤6) · Browse by specialty (≤12 tiles) · Browse by society (8 tiles) · HowItWorks. Every row/tile links into `/conferences…` or `/conferences/[id]`.
- Auth plumbing: middleware redirects signed-out users to a bare `/auth/login` (no `?next=`); login always pushes `/conferences` after sign-in (`src/app/auth/login/page.tsx:63`); `safeNextPath` exists (`src/lib/auth/password.ts:23`) but only the callback uses it. Existing prompt patterns: AddInfoDialog/SubmitEventForm inline `SignInPrompt` card; EventSidebar save → hard redirect; `AccountEmptyState`. Save/reminder controls silently do nothing when signed out.
- SEO: no `sitemap.ts`/`robots.ts`/`metadataBase`; detail pages carry OpenGraph + Event JSON-LD and are commented "public and indexable".
- Tests: directory-url/query/source covered; NOTHING covers the homepage, `/conferences`, `/societies`, middleware or `/api/directory`.
- Consequence: an app-only gate still leaves every row readable to anyone who opens devtools and calls PostgREST with the anon key the browser already holds.

## Design inputs (HQ skills consulted)
- `ui-ux-pro-max` landing patterns: **Marketplace/Directory** ("search bar is the CTA; reduce friction to search; popular searches") and **Community** ("preview content, show activity counts, easy onboarding"). Stack rule: gate in `middleware.ts` with a specific matcher, not per page.
- `web-arm/LIBRARY.md` routing: landing-page build → lead **taste-skill** (+ tailwind-patterns), taste gate **frontend-design**; QA §6; SEO → **seo-fundamentals** + **schema-markup**. `react-ui-patterns`: every gated collection must render an explicit state, never blank. §10: paywall/signup CRO skills are DORMANT — one operator gate away if wanted for phase 3.
- `emil-design-eng`: the sign-in prompt is an occasional modal → centred `transform-origin`, enter from `scale(.95)`+opacity, ease-out ≤200 ms; no animation on the frequent path (typing in search); buttons `scale(.97)` on press.

## Recommended approach — three layers, two phases
### Phase 1 — route gate + public front door (ship first; reversible)
1. **Route gate** (`src/middleware.ts`): add `/conferences` (list) and `/societies` to `PROTECTED_PATHS`; redirect signed-out visitors to `/auth/login?next=<path+query>`; signup link carries the same `next`; login and signup honour it through `safeNextPath` (fallback `/conferences`). Add `/api/directory` to the gated set: anonymous → `401 {error:"sign_in_required"}` with `Cache-Control: private, no-store`; signed-in → as today but `private`. (DuplicateCheck and moderation search already sit behind sign-in.) CommandPalette hidden for signed-out users (Navbar already knows the session).
2. **Event detail = soft gate** (`/conferences/[id]`): stays reachable (every teaser links there; keeps shareable links, OpenGraph, Event JSON-LD). Anonymous render = header (name, society, specialty, dates, city/online) + a `LockedPanel` in place of fees, CPD, abstract deadline, venue, booking/organiser links, sessions, save/reminder. Values are NOT sent to the client for anonymous users (server decides via a cookie-aware client + `getUser()`); no blur-of-real-data.
3. **Homepage = public front door** (anonymous): Hero with the search box kept ("search bar is the CTA") — submitting opens the `SignInGate` dialog carrying `next=/conferences?q=…`; live aggregate proof (events, societies, specialties, abstracts closing this fortnight — counts only); **Closing soon** ≤5 rows showing name · society · "closes in N days" (exact date + CFP link locked); **This month** ≤6 rows (name · society · dates); **Browse by specialty** tiles with counts and **Browse by society** tiles → tap opens `SignInGate` with the matching `next`; HowItWorks step 1 becomes "Create a free account". Metadata/hero copy: "Free account" replaces "no account needed". Signed-in visitors: same page, rows/tiles link straight through (no gate), plus their saved/reminders strip (later).
4. **Shared components**: `src/components/auth/SignInPrompt.tsx` (promote the AddInfoDialog inline card), `SignInGate` (Radix Dialog wrapper, carries `next`, two CTAs + one benefit line), `LockedPanel` (list of what unlocks + the same CTAs). All built on the existing tokens; previewed on `/design`.
5. **SEO**: `robots.ts` + `sitemap.ts` (home, auth, soft-gated detail pages); `noindex` on `/conferences` and `/societies` (they now redirect); `metadataBase`; Event JSON-LD keeps dates/location, drops Offer for anonymous (no fee values) and adds `isAccessibleForFree: false`.
6. **Tests (red first)**: middleware path matrix (anon → 307 with `next`; signed-in → 200); login/signup honour `next` only via `safeNextPath`; `/api/directory` 401 + no-store for anon; homepage server render for anon contains no fee/CPD/deadline-date strings and no `/conferences?` links without the gate; detail page anonymous render has no fee values; `check:societies` and the 329 vitest green.

### Phase 2 — data gate (closes the anon-key loophole; needs a migration)
7. Revoke anon reads: policies `TO authenticated` on `conferences`, `pricing_tiers`, `course_sessions`, `scraper_sources`, published `community_facts/tiers`; revoke anon on `directory_events` and `directory_facets()`. Scraper/remediator (service role) unaffected.
8. Two narrow `SECURITY DEFINER` RPCs for the public surface, granted to anon, bounded and sparse: `home_preview()` (counts; ≤5 closing-soon rows with relative deadline only; ≤6 this-month rows; specialty + society tiles with counts) and `event_preview(id)` (the header fields only). Homepage and detail-teaser read these when anonymous; everything else uses the cookie-aware client so RLS sees the user's JWT.
9. `/api/directory`, `/conferences`, `/societies`, `/conferences/[id]` switch to the cookie-aware server client. Migration applied via `apply_migration.py` with checks; staged: Phase 1 live first, Phase 2 behind a short soak.

### Phase 3 (optional, operator gate) — conversion polish
Activate the dormant signup/paywall CRO skills for copy and prompt placement; add a signup-conversion metric (Vercel Analytics or Supabase auth signups/day) to judge the gate.

## Trade-offs the owner is accepting
- `/conferences` and `/societies` stop being indexable; the homepage and soft-gated event pages carry the SEO instead. The "no account needed" promise disappears.
- Friction before value: mitigated by the search-as-CTA flow (intent preserved through `next`) and by showing real counts/names on the front door.
- Phase 2 is the only thing that truly hides data; Phase 1 alone is a UX gate.
